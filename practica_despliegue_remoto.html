Fork en GitHub, arquitectura Cloud (Backend en Render / GCP / AWS + DBaaS en MongoDB Atlas), regla 0.0.0.0/0 y mejora con desplegable de listas dinámico.

⏱️ Duración estimada: 2.5 horas 🍴 Requisito: Fork obligatorio 🚀 Cloud: Render, GCP, AWS, Atlas 📦 Entregables: URL pública + Capturas + Vídeo 1 min
🌍 El Salto de "Localhost" al Mundo Real

En esta práctica daremos el gran salto a producción: realizarás un Fork en GitHub, desplegarás el archivo [awcodeAtlas.js](file:///Users/fjbanezares/express-mongo-hands-on/awcodeAtlas.js) en un proveedor de infraestructura Cloud (sugerido Render, con opciones en Google Cloud Run o AWS) conectado a una base de datos gestionada en MongoDB Atlas. Además, implementarás una mejora personalizada con tu nombre (un menú desplegable interactivo para saltar de una lista a otra) y verificarás la app en vivo desde tu teléfono móvil.

Paso 1

Configuración de MongoDB Atlas y la Regla 0.0.0.0/0

1. Crear Clúster M0 (Gratuito) y Usuario de Base de Datos

  1. Entra en mongodb.com/cloud/atlas y crea un clúster gratuito (Shared M0).
  2. En Security > Database Access, crea un usuario (ej: appUser) con una contraseña segura. ¡Anota bien la contraseña!
🚨 ¡ATENCIÓN CRÍTICA: Por qué DEBES poner 0.0.0.0/0 en Network Access!

En Atlas ve a Security > Network Access > Add IP Address y selecciona Allow Access from Anywhere (que añade la IP 0.0.0.0/0).

¿Por qué si no haces esto la aplicación en la nube va a "petar" con error de conexión?

En tu casa, tu ordenador tiene una IP fija o conocida. Pero los servidores en la nube como Render, Google Cloud Run o AWS funcionan mediante contenedores efímeros cuya IP pública de salida cambia constantemente con cada reinicio o petición.
Si dejas en Atlas solo tu IP local, tu app funcionará en tu ordenador, pero en cuanto Render intente conectarse, el cortafuegos de MongoDB Atlas bloqueará la petición con el temido error MongoServerSelectionError: connection timed out.
Nota de seguridad: Permitir 0.0.0.0/0 es el estándar en PaaS/Serverless; la seguridad descansa en la autenticación criptográfica de tu usuario y contraseña (SCRAM-SHA-256) y en no exponer tu cadena de conexión en GitHub.

2. Obtener tu Connection String

En Atlas, pulsa Connect > Drivers (Node.js) y copia tu URL:

mongodb+srv://appUser:<password>@cluster0.abcde.mongodb.net/todolistDB?retryWrites=true&w=majority
Reto de Código Obligatorio

🌟 Mejora de Código: Desplegable de Navegación («Listas tareas de XXX»)

Antes de desplegar en la nube, implementaremos una mejora diferencial en la interfaz: un desplegable en la cabecera que consulte todas las listas existentes en MongoDB Atlas y permita cambiar de una a otra con un solo clic.

🏷️ FACTOR DIFERENCIAL PERSONALIZADO: El desplegable debe titularse obligatoriamente Listas tareas de XXX, donde XXX es tu nombre y apellido real (ejemplo: "Listas tareas de Laura Sánchez").

Paso A: Modificar el Backend (awcodeAtlas.js)

En awcodeAtlas.js, asegura que la conexión use variable de entorno y que las rutas GET / y GET /:customListName consulten todas las listas para enviarlas a la vista:

// 1. Configuración de conexión segura con variable de entorno
const MONGODB_ATLAS_URI = process.env.MONGODB_URI || "tu_uri_de_atlas_aqui";
mongoose.connect(MONGODB_ATLAS_URI, { useNewUrlParser: true, useUnifiedTopology: true });

// 2. En la ruta GET / y en GET /:customListName:
// Consultamos todas las listas existentes antes de renderizar
const allLists = await List.find({}, "name");

res.render("list", { 
    listTitle: "Today", 
    newListItems: foundItems,
    allLists: allLists   // 👈 Añadir esta variable
});

Paso B: Modificar la Vista EJS (views/list.ejs)

En views/list.ejs, añade el siguiente bloque dentro de <div class="box" id="heading"> justo debajo de <h1><%= listTitle %></h1>:

<!-- DESPLEGABLE DINÁMICO DE NAVEGACIÓN ENTRE LISTAS -->
<% if (typeof allLists !== 'undefined' && allLists.length > 0) { %>
  <div style="padding-bottom: 18px; text-align: center;">
    <label for="listNav" style="color: #ffffff; font-size: 13.5px; display: block; margin-bottom: 6px; font-weight: 500;">
      📋 Listas tareas de XXX:  <!-- 👈 REEMPLAZA XXX POR TU NOMBRE -->
    </label>
    <select id="listNav" 
            onchange="if(this.value) window.location.href = (this.value === 'Today' ? '/' : '/' + encodeURIComponent(this.value));"
            style="padding: 7px 12px; border-radius: 8px; border: 1px solid #ccc; font-size: 14px; background: #ffffff; color: #333; cursor: pointer; outline: none;">
      <option value="">-- Cambiar de lista --</option>
      <option value="Today" <%= listTitle === 'Today' ? 'selected' : '' %>>📅 Today</option>
      <% allLists.forEach(function(l) { %>
        <% if (l.name !== 'Today') { %>
          <option value="<%= l.name %>" <%= listTitle === l.name ? 'selected' : '' %>>
            📌 <%= l.name %>
          </option>
        <% } %>
      <% }); %>
    </select>
  </div>
<% } %>

Paso 3

Despliegue del Backend en la Nube

⭐ Opción A (Recomendada): Despliegue en Render

  1. Regístrate en render.com con tu cuenta de GitHub.
  2. Haz clic en New + > Web Service.
  3. Selecciona TU FORK (TU_USUARIO/express-mongo-hands-on).
  4. Configura los campos:
    • Name: todolist-tu-nombre
    • Region: Frankfurt (EU) u Ohio (US)
    • Runtime: Node
    • Build Command: npm install
    • Start Command: node awcodeAtlas.js
    • Instance Type: Free
  5. Variables de Entorno (Crucial): En la pestaña Environment Variables, añade:
    Key: MONGODB_URI
    Value: Tu cadena completa de MongoDB Atlas con tu usuario y contraseña.
  6. Pulsa Deploy Web Service.

En unos minutos Render emitirá tu URL pública oficial con HTTPS (ej: https://todolist-tu-nombre.onrender.com).
